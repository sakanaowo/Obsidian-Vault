Tiếp tục đúng thứ tự sang Bước 8.2 — Mode Popup UI.

Theo thiết kế đã chốt, btnMode sẽ mở một menu tối, bo góc, gồm đúng 3 lựa chọn:

✓ Basic
  Scientific
  Convert

Mode hiện tại phải có dấu chọn; việc bấm chọn và chuyển mode thật sẽ nối ở bước sau.   WBS cũng tách rõ Mode model → Mode popup → Mode switching, nên bước này chỉ dựng resource/UI, chưa sửa logic chuyển màn hình.

8.2.7 — Tại sao Basic check mặc định visible?

Trong XML:

android:visibility="visible"

cho:

checkModeBasic

vì app hiện mặc định:

currentMode =
        CalculatorMode.BASIC;

Hai mode khác:

android:visibility="gone"

Tuy nhiên đây chỉ là default XML.

Ở bước 8.3 Java sẽ luôn sync theo currentMode:

currentMode = BASIC
↓
check Basic = visible
currentMode = SCIENTIFIC
↓
check Scientific = visible
currentMode = CONVERT
↓
check Convert = visible

Do đó không phụ thuộc cứng vào Basic.

⸻

8.2.8 — Vì sao chưa có icon f(x) hoặc Convert?

Thiết kế tham khảo cho phép row có icon, label và checkmark. Nhưng trong MVP, phần quan trọng nhất của Mode Popup là:

Mode name
+
selected state
+
touch target

Ta chưa thêm:

calculator icon
f(x) icon
convert icon

để tránh tạo resource không ảnh hưởng chức năng trước khi switching hoạt động.

Sau khi M3 chạy ổn, icon có thể được thêm ở UI Polish mà không đổi kiến trúc.

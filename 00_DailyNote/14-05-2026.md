## 🔷 PHẦN 1: RAG-project — Vietnamese Legal Bidding Law Q&A

### 1.1 Kiến Trúc RAG Pipeline

**Q1: Mô tả flow xử lý một câu hỏi từ user đến khi trả về answer trong RAG system của bạn.**

> [!info]- 📌 Đáp án
> 1. User gửi query qua FastAPI endpoint
> 2. **Semantic Cache check** (L1 in-memory LRU → L2 Redis → L3 PostgreSQL) — nếu hit thì trả về cached answer
> 3. **Query Enhancement**: MultiQueryRetriever / StepBackRetriever tạo nhiều biến thể query
> 4. **Retrieval**: Vector search trên pgvector (cosine similarity, 3072-dim OpenAI `text-embedding-3-large`)
> 5. **Deduplication**: Loại bỏ chunks trùng lặp dựa trên content hash
> 6. **Reranking**: BGE-reranker-v2-m3 cross-encoder rerank top candidates
> 7. **Generation**: GPT-4o-mini sinh câu trả lời dựa trên retrieved context
> 8. **Cache store**: Lưu answer vào semantic cache cho lần sau

---

**Q2: Giải thích cơ chế Semantic Cache V2 (Hybrid Cosine + BGE Rerank). Tại sao không dùng BGE trực tiếp cho tất cả cached queries?**

> [!info]- 📌 Đáp án
> - **Vấn đề**: BGE cross-encoder có độ chính xác cao nhưng O(n) rất chậm (~9000ms cho 1000 queries)
> - **Giải pháp Hybrid**:
>   1. **Cosine pre-filter**: Dùng stored OpenAI embeddings, tính cosine similarity nhanh (~5ms/1000 queries), lọc top-30 candidates (threshold=0.25, thấp để không miss)
>   2. **BGE rerank**: Chỉ rerank 30 candidates (~180ms) thay vì 1000
>   3. **Total**: ~450ms vs 9000ms — nhanh hơn 20x
> - **Config**: `cosine_threshold=0.25` (pre-filter), `bge_threshold=0.55` (final match, 78.9% accuracy)
> - Redis DB3 lưu embeddings, TTL 24h matching answer cache

---

**Q3: Multi-tier caching architecture (L1/L2/L3) hoạt động thế nào?**

> [!info]- 📌 Đáp án
> | Layer | Storage | Capacity | Latency | TTL |
> |-------|---------|----------|---------|-----|
> | L1 | In-memory LRU | 100 queries | <1ms | Session |
> | L2 | Redis (pickle) | Unlimited | ~2ms | 24h |
> | L3 | PostgreSQL | Unlimited | ~10ms | Persistent |
> 
> - Lookup order: L1 → L2 → L3 → Full RAG pipeline
> - Write-through: Kết quả mới được ghi vào cả 3 layers
> - L1 dùng Python `functools.lru_cache` hoặc custom OrderedDict

**Q4: Tại sao chọn `text-embedding-3-large` (3072-dim) thay vì model nhỏ hơn?**

> [!info]- 📌 Đáp án
> - **Accuracy**: 3072-dim cho representation quality cao hơn, quan trọng cho legal domain cần precision
> - **Multilingual**: Hỗ trợ tiếng Việt tốt hơn các model cũ
> - **Trade-off**: Dimension lớn → storage/compute nhiều hơn, nhưng pgvector + IVFFlat index vẫn đạt ~50ms search latency
> - Có thể dùng `dimensions` parameter để truncate xuống 256/1024 nếu cần tiết kiệm

**Q7: BGE-reranker-v2-m3 là gì? Cross-encoder khác bi-encoder thế nào?**

> [!info]- 📌 Đáp án
> - **Bi-encoder** (embedding model): Encode query và document **độc lập** → so sánh bằng cosine. Nhanh nhưng kém chính xác vì không thấy interaction giữa query-doc
> - **Cross-encoder** (BGE reranker): Nhận **cặp (query, document)** đồng thời → attention giữa query và doc tokens → score chính xác hơn. Chậm vì phải chạy cho mỗi cặp
> - **BGE-reranker-v2-m3**: Multilingual (180+ ngôn ngữ), fine-tuned cho reranking task, max 512 tokens
> - **Singleton pattern**: Model ~1.2GB, load 1 lần và reuse. Thread-safe với double-checked locking
> - **CUDA OOM fallback**: Tự động chuyển sang OpenAI reranker nếu GPU hết memory

## 🔷 PHẦN 2: PlantXMamba — Vision-Mamba Plant Disease Classification

### 2.1 Model Architecture

**Q9: Mô tả kiến trúc hybrid của PlantXMamba.**

> [!info]- 📌 Đáp án
> PlantXMamba kết hợp 4 thành phần:
> 1. **VGG16 backbone** (pretrained ImageNet): Trích xuất low-level và mid-level features
> 2. **Inception-style conv block**: Multi-scale feature extraction (1×1, 3×3, 5×5 parallel convolutions) → capture patterns ở nhiều kích thước
> 3. **Patch Embedding**: Chia feature maps thành patches, flatten + linear projection thành sequence of tokens
> 4. **Mamba sequence modeling**: State Space Model (SSM) xử lý sequence of patches — thay thế Transformer self-attention với linear complexity O(n) thay vì O(n²)

---

**Q10: Mamba (State Space Model) khác Transformer thế nào? Ưu điểm gì?**

> [!info]- 📌 Đáp án
> | Aspect | Transformer | Mamba (SSM) |
> |--------|------------|-------------|
> | Complexity | O(n²) self-attention | O(n) linear |
> | Memory | Quadratic với sequence length | Linear |
> | Long-range | Attention decay | SSM parameters model long-range natively |
> | Inference | Cần full sequence | Có thể recurrent (streaming) |
> 
> - **Selective State Space**: Mamba thêm input-dependent selection mechanism — parameters A, B, C, Δ phụ thuộc vào input → model có thể "chọn" thông tin quan trọng
> - Cho image classification: Patches được xử lý như sequence, Mamba capture spatial relationships giữa patches hiệu quả

---

**Q11: Tại sao dùng VGG16 pretrained thay vì train from scratch?**

> [!info]- 📌 Đáp án
> - **Transfer learning**: VGG16 đã học rich feature representations từ ImageNet (1.2M images, 1000 classes)
> - **Data efficiency**: PlantVillage dataset nhỏ hơn nhiều → train from scratch dễ overfit
> - **Feature hierarchy**: VGG16 cung cấp low-level (edges, textures) → mid-level (patterns) features tốt cho plant disease symptoms
> - **Fine-tuning**: Freeze early layers, chỉ train later layers + Mamba head

---

**Q12: Giải thích kết quả: 98.71% PlantVillage nhưng chỉ 88.16% Embrapa. Tại sao?**

> [!info]- 📌 Đáp án
> - **PlantVillage**: Ảnh chụp trong điều kiện controlled (lab), background sạch, lighting đồng nhất → dễ classify
> - **Embrapa**: Ảnh thực tế (field conditions), background phức tạp, lighting thay đổi, nhiều noise → khó hơn
> - **Domain gap**: Model trained chủ yếu trên PlantVillage-style images, generalize kém hơn ra real-world
> - **Possible improvements**: Data augmentation mạnh hơn, domain adaptation techniques

## 🔷 PHẦN 3: TouchlessControl — Hand Gesture Recognition

### 3.1 Pipeline Architecture

**Q13: Mô tả full pipeline từ camera frame đến OS action.**

> [!info]- 📌 Đáp án
> ```
> Camera (V4L2, MJPG 720p@30fps)
>   → cv2.flip (mirror)
>   → MediaPipe Hands (21 landmarks, 3D)
>   → FeatureExtractor (93-dim vector)
>   → SequenceBuffer (circular buffer, window=20 frames)
>   → TemporalClassifier (GRU-64 TFLite, ~91KB)
>   → Debouncer (confidence threshold + cooldown)
>   → ActionMapper (pynput/ydotool → OS mouse/keyboard)
> ```
> 
> - **Continuous gestures** (pointer_move, scroll_mode): Bypass Debouncer, trực tiếp điều khiển CursorController / ScrollController
> - **Event gestures** (left_click, drag): Qua Debouncer → ActionMapper.handle()

---

**Q14: FeatureExtractor tạo 93-dim vector như thế nào? Tại sao 93?**

> [!info]- 📌 Đáp án
> 5 blocks:
> 1. **3D coordinates** (63 features): 21 keypoints × 3 (x,y,z), normalized relative to wrist, scaled by max distance
> 2. **Joint angles** (15 features): Cosine of angles tại mỗi joint của 5 ngón tay (3 joints/ngón)
> 3. **Tip-to-wrist distances** (5 features): Khoảng cách từ 5 fingertip đến wrist, normalized
> 4. **Tip-to-palm distances** (5 features): Khoảng cách từ 5 fingertip đến palm center (mean of [0,5,9,13,17])
> 5. **Finger states** (5 features): Binary (0/1) — ngón duỗi hay gập (so sánh tip_dist vs pip_dist to wrist)
> 
> **Total**: 63 + 15 + 5 + 5 + 5 = **93**
> 
> So với legacy 42-dim (chỉ XY): 93-dim thêm depth (Z), angles, distances → robust hơn với rotation và scale

---

**Q15: Tại sao dùng GRU thay vì LSTM hoặc Transformer cho temporal classification?**

> [!info]- 📌 Đáp án
> - **GRU vs LSTM**: GRU có ít parameters hơn (2 gates vs 3 gates), inference nhanh hơn — quan trọng cho real-time (30fps)
> - **Model size**: GRU-64 chỉ ~91KB (TFLite quantized) → chạy được trên mọi laptop
> - **Sequence length**: Window chỉ 20 frames — ngắn, không cần long-range dependency của Transformer
> - **Latency**: TFLite inference ~1-2ms vs Transformer sẽ chậm hơn nhiều
> - **Temporal smoothing**: GRU tự nhiên smooth predictions qua thời gian, giảm jitter

---

**Q16: SequenceBuffer (circular buffer) hoạt động thế nào?**

> [!info]- 📌 Đáp án
> - **Circular overwrite**: `pos = count % window_size` — khi buffer đầy, frame mới ghi đè frame cũ nhất
> - **get_window()**: Trả về array (W, 93) theo thứ tự chronological
>   - Nếu `count >= window_size`: Roll buffer để oldest→newest order
>   - Nếu `count < window_size`: Zero-pad ở đầu
> - **is_ready()**: True khi đã push >= window_size frames
> - **Ưu điểm**: O(1) push, O(W) get_window, no memory allocation — tối ưu cho real-time

---

**Q17: Debouncer vs GestureStateMachine — khi nào dùng cái nào?**

> [!info]- 📌 Đáp án
> | | Debouncer (GRU mode) | GestureStateMachine (MLP mode) |
> |---|---|---|
> | **Dùng khi** | `--model gru` | `--model mlp` |
> | **Logic** | Nhẹ: confidence threshold + edge detection + cooldown | Phức tạp: idle→tracking→active states |
> | **Tại sao** | GRU đã temporal smoothing rồi → chỉ cần detect edges | MLP single-frame, cần state machine để stabilize |
> | **Activation** | 1 confident frame = start | 5 consecutive frames (activation_frames) |
> | **Deactivation** | 1 null frame = end | 10 consecutive frames |
> 
> - **GestureEvent**: `(gesture_name, event_type)` với event_type = "start" / "hold" / "end"
> - ActionMapper dispatch dựa trên event_type: start→fire action, hold→fire if repeat:true, end→release drag

---

**Q18: ActionMapper xử lý cross-platform input thế nào?**

> [!info]- 📌 Đáp án
> Backend detection order:
> 1. **DISPLAY set** (X11/XWayland) → `pynput` (preferred, fast, no extra install)
> 2. **WAYLAND_DISPLAY set** + `ydotool` available → ydotool subprocess
> 3. **None** → RuntimeError, cần `--no-actions`
> 
> - Config từ `config/gesture_actions.yaml` — mapping gesture→action
> - Action types: `key_press`, `key_combo`, `mouse_click`, `mouse_drag`, `scroll`
> - `mouse_drag`: Press on "start" event, release on "end" event
> - Camera: V4L2 trên Linux (MJPG codec), `exposure_dynamic_framerate=0` để fix 10fps issue

## 🔷 PHẦN 4: Kiến Thức Nền Tảng Cross-Project

### 4.1 Vector Databases & Embeddings

**Q20: Cosine similarity vs Euclidean distance cho vector search — khi nào dùng cái nào?**

> [!info]- 📌 Đáp án
> - **Cosine similarity**: Đo góc giữa vectors, invariant với magnitude. Tốt cho text embeddings vì documents có độ dài khác nhau
> - **Euclidean (L2)**: Đo khoảng cách tuyệt đối. Tốt khi magnitude có ý nghĩa
> - **pgvector**: Hỗ trợ cả hai, project dùng cosine (`<=>` operator)
> - **Normalized vectors**: Khi vectors đã normalized (unit length), cosine và L2 cho cùng ranking

---

**Q21: pgvector indexing — IVFFlat vs HNSW?**

> [!info]- 📌 Đáp án
> | | IVFFlat | HNSW |
> |---|---|---|
> | Build time | Nhanh | Chậm |
> | Query time | Trung bình | Nhanh hơn |
> | Memory | Thấp | Cao hơn |
> | Accuracy | Phụ thuộc nprobes | Ổn định hơn |
> 
> - Project dùng **native cosine similarity** (exact search) cho 63 documents → nhanh đủ (~50ms)
> - IVFFlat/HNSW chỉ cần khi scale lên millions of vectors

### 4.2 Deep Learning Fundamentals

**Q22: GRU (Gated Recurrent Unit) — giải thích kiến trúc.**

> [!info]- 📌 Đáp án
> 2 gates:
> - **Reset gate** `r = σ(W_r · [h_{t-1}, x_t])`: Quyết định bao nhiêu past state cần "quên"
> - **Update gate** `z = σ(W_z · [h_{t-1}, x_t])`: Quyết định bao nhiêu new info cần "nhớ"
> - **Candidate** `h̃ = tanh(W · [r * h_{t-1}, x_t])`: New candidate state
> - **Output** `h_t = (1-z) * h_{t-1} + z * h̃`: Interpolation giữa old và new
> 
> So với LSTM: Không có cell state riêng, ít parameters hơn → nhanh hơn, performance tương đương trên short sequences

---

**Q23: TFLite quantization — tại sao model chỉ 91KB?**

> [!info]- 📌 Đáp án
> - **Post-training quantization**: Convert FP32 weights → INT8 (4x nhỏ hơn)
> - **GRU-64**: Chỉ 64 hidden units → rất ít parameters
> - Input: (1, 20, 93) = 1860 values, Output: (1, 5) = 5 classes
> - Total params ước tính: ~50K → FP32 ~200KB → INT8 ~50KB + overhead = ~91KB
> - **TFLite runtime**: Lightweight inference engine, không cần full TensorFlow

---

**Q24: Transfer Learning — Fine-tuning strategy cho VGG16 trong PlantXMamba?**

> [!info]- 📌 Đáp án
> - **Freeze early layers** (conv1-conv3): Giữ nguyên low-level features (edges, textures)
> - **Fine-tune later layers** (conv4-conv5): Adapt mid/high-level features cho plant domain
> - **Replace classifier**: Bỏ VGG16 FC layers, thay bằng Inception block + Mamba head
> - **Learning rate**: Lower LR cho pretrained layers (1e-5), higher cho new layers (1e-3)
> - **Batch normalization**: Thêm BN layers giữa các blocks để stabilize training

### 4.3 System Design & Engineering

**Q25: Singleton pattern — tại sao dùng trong cả RAG (BGEReranker) và TouchlessControl?**

> [!info]- 📌 Đáp án
> - **BGEReranker**: Model ~1.2GB, load mất ~5-10s. Singleton đảm bảo load 1 lần, reuse across requests
> - **HybridSemanticCache**: Redis connection pool shared across threads
> - **Thread-safety**: Double-checked locking pattern — check trước lock (fast path), check lại trong lock (race condition prevention)
> - **TouchlessControl**: Không dùng singleton vì single-threaded, nhưng lazy initialization tương tự
> 
> ```python
> # Double-checked locking pattern
> if _instance is not None:       # Fast path (no lock)
>     return _instance
> with _lock:
>     if _instance is None:       # Re-check inside lock
>         _instance = create()
>     return _instance
> ```

**Q26: Vertex AI Search migration — giải thích Discovery Engine architecture.**

> [!info]- 📌 Đáp án
> - **Engine** > **DataStore** > **Documents**: Hierarchical structure
> - **Serving config**: Phải dùng engine-level path (không phải datastore-level) để có extractive answers
> - **Enterprise tier**: Required cho extractive answers — `SEARCH_TIER_ENTERPRISE`
> - **Filter expressions**: `user_id: ANY("user123", "__system__")` cho document scoping
> - **User-first reranking**: Khi doc_scope="all", user docs xếp trước system docs

> ```
> projects/{project}/locations/{location}/collections/default_collection/engines/{engine}/servingConfigs/default_config

### 4.4 LangGraph (AIServices — Bonus)

**Q27: LangGraph StateGraph pattern trong AIServices project.**

> [!info]- 📌 Đáp án
> - **AgentState** (TypedDict): Central state flowing through all nodes
> - **Nodes**: supervisor → math_agent → reviewer → formatter → END
> - **Conditional edges**: supervisor routes to agent by content_type; reviewer routes pass→formatter, fail→math_agent (retry)
> - **Annotated[list, add]**: Accumulate items across iterations (reviewed_items, rejected_items, errors)
> - **MAX_REVIEW_ITERATIONS = 5**: Prevent infinite retry loops
> 
> Flow: Request → Supervisor (classify) → Agent (retrieve + generate) → Reviewer (quality gate) → Formatter (game output)
